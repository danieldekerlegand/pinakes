## Codebase Patterns
- TSV files live in `lexicons/` directory — all data storage uses TSV format
- Language IDs in data files must match the `id` column in `lexicons/languages.tsv`
- Pre-existing typecheck errors exist in visualization and map components — not related to new data work
- Genre values for sample-texts: prose, poetry, religious, legal, inscription, conversational
- Language detail panel uses collapsible sections with `enabled: showX` lazy-loading pattern for data queries
- Old Irish (sga) is not in languages.tsv; used `gle` (Irish) as substitute
- Classical Chinese is not in languages.tsv; used `och` (Old Chinese) as closest match
- TSV loader pattern: `parseTsv()` + `getIdx()` (required) / `header.indexOf()` (optional), cache in `private cachedX`, lazy-load in `private loadX()`
- API route pattern: try/catch, list endpoints return `{ items, count, filters }`, single-item endpoints return object or 404
- Etymology relation direction: source_word is derived FROM target_word — ancestors go source→target, descendants go target→source
- Etymology trace uses `traceEtymology`/`traceDescendants` from `server/services/etymology-trace.ts`

## 2026-03-12 - US-006
- Created `server/services/etymology-trace.ts` with `traceEtymology` and `traceDescendants` functions
- Both functions recursively follow `derived_from`, `etymology`, and `borrowed_from` relations
- Circular reference protection via visited-set using `word|language` composite keys
- Returns tree structure: `{ word, language, relation, children: [...] }`
- Added `GET /api/etymology-relations/trace/:word` endpoint with optional `?language=` and `?direction=descendants` query params
- Registered route in `server/routes.ts`
- Files changed: `server/services/etymology-trace.ts` (created), `server/routes.ts`
- **Learnings for future iterations:**
  - Etymology relations are directional: source_word is derived FROM target_word for `derived_from`, `etymology`, `borrowed_from`
  - Tracing ancestors = follow source→target; tracing descendants = follow target→source
  - The trace endpoint supports `?direction=descendants` to reverse the trace direction
  - `cognate` relations are excluded from tracing since they're peer relationships, not parent-child
  - Route ordering: `/trace/:word` and `/word/:word` don't conflict since Express matches the static segment (`trace` vs `word`) before the param
